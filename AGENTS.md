# Reglas del Proyecto Yomi

## REGLA — NO USAR COMANDOS DE GIT
- **PROHIBIDO** ejecutar comandos de git (`git status`, `git diff`, `git log`, `git add`, `git commit`, `git checkout`, `git stat`, etc.).
- El control de versiones es gestionado exclusivamente por el usuario.
- No correr comandos de git para verificar estado, cambios ni diffs; proceder directamente con el código, compilación y pruebas sin interactuar con git.

## REGLA — USAR DEPENDENCIAS ACTUALIZADAS Y MODERNAS (NO HERRAMIENTAS OBSOLETAS)
- **PROHIBIDO** utilizar APIs, módulos o herramientas obsoletas/legacy (como el módulo antiguo `Animated` de `react-native`, o timers manuales de JS `setTimeout` para coordinar animaciones) cuando el proyecto ya cuenta con dependencias modernas y potentes como **`react-native-reanimated` (v4+)**.
- Utilizar siempre `react-native-reanimated` y `react-native-gesture-handler` para micro-interacciones, transiciones de pantalla, modales y layouts en el UI thread.
- Utilizar las Layout Animations nativas de Reanimated (`entering`, `exiting`, `layout={LinearTransition}`) para chips, reordenamientos y filtros de listas.
- Respetar la New Architecture de React Native (React 19 / Expo 57) y no reinventar la rueda con hacks manuales.
## REGLA — MOTOR DE VOZ (SHERPA-ONNX: REAZONSPEECH + SENSEVOICE)
- Reconocimiento offline con Sherpa-ONNX (`lib/sherpa-service.ts`), un modelo por idioma: **japonés → ReazonSpeech** (zipformer transducer INT8, ~160 MB) y **chino / inglés → SenseVoice-Small** (INT8, ~230 MB). Otros idiomas usan el reconocedor nativo (`expo-speech-recognition`). El único punto de entrada es `lib/speech-recognition-service.ts`.
- **Pistas (hotwords) en japonés:** en cada intento se le pasa a ReazonSpeech SOLO la palabra de la tarjeta actual (`expectedVoiceWords`: su escritura y la lectura que muestra; NO el catálogo de lecturas on/kun, cuyos fragmentos hacían intercalar kanas), con peso 1.5. La pista inclina al modelo hacia la palabra cuando el audio es dudoso (まん en vez de ま) pero no la inventa si no se dijo. Nunca pasar pistas de otras tarjetas: compiten (こう de otra tarjeta convertía "ko" en こう).
- **Los modelos NO van dentro del APK.** El usuario descarga solo el del idioma que estudia, en `documentDirectory/models/<modelo>`, desde Configuración › Prueba de audio › Reconocimiento de voz (`useVoiceModelStore`). La app NUNCA los descarga sola: si falta, avisa y ofrece ir a Configuración. Se cargan en memoria solo al usarse (nunca al abrir la app).
- **Un intento = una elocución completa.** Sherpa entrega un único resultado final por cada frase seguida de una pausa. En el repaso hay 3 intentos por tarjeta.
- **El recorrido del repaso por voz** (cuándo se abre y se reabre el micrófono, se evalúa, se lee la palabra y se pasa de tarjeta) es una máquina de estados pura en `lib/review-flow.ts`; `src/hooks/review/useVoiceReview.ts` solo ejecuta lo que pide. Los avisos viejos se descartan por número de tarjeta/apertura del micrófono, no con banderas ni temporizadores. El reconocedor del teléfono se cierra solo tras un silencio y avisa "end" una vez por apertura (`lib/speech-recognition-service.ts`). Antes de cada OTA correr `npm run test:review` y `npm run test:voice`: los dos deben dar "Todo bien" / 0 falsos aciertos.
- **La práctica de conjugaciones** sigue la misma idea con su propia máquina de estados, `lib/practice-flow.ts` (la ejecuta `src/components/ConjugationPracticeModal.tsx`; prueba: `npm run test:practice`). Un intento por tarjeta. Modo automático (mantener apretado el micrófono): se reabre solo al cerrarse por silencio y al pasar de tarjeta; un error real del reconocedor lo apaga (nunca reintentar en bucle) y se apaga solo tras varios cierres seguidos sin oír nada. La respuesta (dicha o escrita) se evalúa con `matchesConjugationAnswer` (`lib/voice-match.ts`), más estricta que el repaso: en una forma conjugada no se tolera duración de vocales, っ ni un sonido distinto (いて ≠ いって, きて ≠ きいて); solo escrituras equivalentes (kanji homófono, katakana, romaji, cifras, おう/おお, ぢ/づ = じ/ず, は/へ/を) y las formas equivalentes de `equivalentConjugations` (じゃ = では, じゃありません = じゃないです, くないです = くありません, en verbos なくて = ないで). Después de tocarla correr `npm run test:conjugation` y `npm run test:practice`.
- **Evaluación estricta** en `lib/voice-match.ts` (`checkVoiceMatch`): se compara la elocución COMPLETA con la lectura de la tarjeta. Solo se toleran escrituras equivalentes (kanji homófono, katakana, romaji, números en cifras: 26日 = 二十六日, 8がつ = 八月, y は/へ/を escritos donde la palabra lleva わ/え/お: かは = かわ), vocales largas y 1 sonido distinto en palabras de 8+ letras. Las tolerancias de sonido (vocales largas, っ, 1 sonido distinto) valen solo si el reconocedor escribió kana; si escribió kanji, se usa su lectura (la de los mazos del usuario y la del diccionario de la app, JMdict; si no está en ninguno, las de cada kanji) y se compara exacta. En chino, homófono es el mismo pinyin con el mismo tono (拾 vale por 十, 是 no), leído en CC-CEDICT. Después de tocar la evaluación o los diccionarios correr `npm run test:voice`: aciertos al 100% y 0 falsos aciertos. Única excepción de sonoridad: en lecturas de UNA mora se acepta oír sonora una consonante sorda (こ→ご), nunca al revés. PROHIBIDO agregar otras tolerancias de prefijo/sufijo, partículas, conjugaciones o sonoridad: generan falsos aciertos.
- `plugins/withSherpaOnnx.js` solo fija propiedades de Gradle.
- **Único parche permitido sobre `node_modules`:** `patches/react-native-sherpa-onnx+0.4.4.patch` (patch-package, se aplica en `postinstall`). Agrega `transcribeSamplesWithHotwords` (pistas por intento, Android; en iOS se ignoran) y activa `modified_beam_search` cuando se pasa `modelingUnit`. Es código nativo: requiere build nuevo (no OTA); la app detecta si el binario lo trae y, si no, transcribe sin pistas. Al actualizar la librería hay que regenerar el parche. PROHIBIDO cualquier otra edición manual de `node_modules`.
